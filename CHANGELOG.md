# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

## [0.3.0] - 2026-10-28

### Added

- Autofix for `langchain-allow-dangerous-code`, `langchain-allow-dangerous-requests` and `langchain-allow-dangerous-deserialization`: `fix-regex` sets the flag to `False`, the library default, with `.fixed.py` fixtures that `semgrep --test` checks (3/3 fix tests pass). README section "Autofix".
- README Troubleshooting section.
- `scripts/tests/`: seeded, time-bounded fuzz tests for `check_metadata.py` and `bundle.py`, scaling tests (the pack on the fixture tree copied 1x and 10x: 1.8s and 4.7s on Semgrep 1.181.0; the metadata lint on ten copies of every rule), and an end-to-end test that installs Semgrep in a fresh venv and runs the README quick start and Example. CI runs them; `make test-scripts` runs the first two.

### Fixed

- `check_metadata.py` and `bundle.py` crashed with a traceback on a rule file that is not UTF-8, is not valid YAML, is nested too deeply, has no `rules` list or holds a rule that is not a mapping; they now exit 2 naming the file. Fields of the wrong type (a number for `message`, a mapping for `metadata.cwe`) are lint problems instead of crashes.
- `check_fixtures.py` now skips `<rule>.fixed.<ext>` files (expected autofix output, not inputs), exits 2 when `--config` has no value or does not exist or when `semgrep` is not on PATH; `bundle.py --out` without a value exits 2.
- README FAQ named the action as `@v1`, a tag that does not exist; it is `@v0`.

### Changed

- The remaining unpinned actions in `ci.yml`, `release.yml` and `action.yml` are pinned by commit SHA.

## [0.2.0] - 2026-10-16

### Fixed

- False positives found by scanning two public agent codebases (modelcontextprotocol/servers and openai/openai-agents-python, 807 files: 32 findings, 22 false positives before, 10 findings and none false after). File-path rules accept helpers named like `validatePath` / `validate_repo_path` as containment checks and no longer treat `Path(...)` as a sink; the Python `llm-api-key-logged` rule no longer taints results of calls that only receive the key; `langchain-dangerous-tools` ignores the OpenAI Agents SDK `ShellTool`; `fastmcp-bind-all-interfaces` ignores `uvicorn.run(app)` and Flask or FastAPI apps (#14). Details in `docs/smoke-test.md`.
- 19 rule messages printed a literal `'$SINK'`, `'$PARAM'`, `'$LOADER'` or `'$TRANSPORT'`; they are reworded and the fixture audit now fails on any unrendered metavariable (#14).
- README examples pinned `@v1` and `v1.0.0`, which never existed; they now use `@v0` and `v0.2.0`. The first release was tagged `v0.1.0`, so its CHANGELOG heading is corrected below.

### Added

- `scripts/check_metadata.py` checks that severity agrees with confidence, likelihood and impact, and that every rule has a `ruleid` and an `ok` fixture line (#14).
- `docs/registry.md`: the two routes to the Semgrep Registry and what each needs (#14).
- ESM `.mjs` and CommonJS `.cjs` child-process fixtures.

### Changed

- Semgrep pinned to 1.181.0 in CI, the release workflow and the action default (#14).
- Removed the umbrella branding; this project stands alone and links its sibling repositories directly.
- The per-rule `metadata.masoon` block is now `metadata.pack`, with the same `pack` and `family` fields. Rule ids are unchanged. Consumers that group SARIF results on the old key need to read the new one.

## [0.1.0] - 2026-10-04

### Added

- 36 rules (23 Python, 13 TypeScript/JavaScript) across seven categories:
  - code-execution: model output to exec/eval, subprocess, os.system and os.popen (Python); child_process, eval, Function and vm (JS/TS).
  - injection: model output to SQL, HTTP requests (SSRF), file paths and HTML/innerHTML.
  - prompt-injection: untrusted input interpolated into system prompts.
  - permissions: LangChain ShellTool and Python REPL tools, allow_dangerous_code and allow_dangerous_requests flags, MCP and agent tool parameters reaching shells and file paths.
  - mcp: FastMCP bound to all interfaces, FastMCP and MCP TypeScript SDK HTTP transports without authentication.
  - secrets: hard-coded provider keys, keys on command lines, keys and environments written to logs.
  - deserialization: torch.load without weights_only, trust_remote_code, pickle-family loaders, unsafe YAML loading, allow_dangerous_deserialization.
- Fixture suite for every rule (`semgrep --test`) plus `scripts/check_fixtures.py`, which fails on any finding outside an annotated line.
- `scripts/check_metadata.py` metadata lint (CWE, OWASP LLM Top 10 2025, confidence, likelihood, impact, references).
- Composite GitHub Action (`action.yml`) with SARIF upload to code scanning and a severity gate.
- Single-file bundle `agentic-semgrep-rules.yaml` (generated by `scripts/bundle.py`, ids prefixed with language and category so the shared Python and JavaScript ids do not collide) for `semgrep --config <raw URL>`; CI fails if it is stale.
- pre-commit hook definition (`language: script`, needs `semgrep` on PATH), Makefile, CI and release workflows.
- Documentation: rule writing guide and smoke test report.
